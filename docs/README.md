## OctoAcme PM Process Overview

OctoAcme follows a documented, iterative project management framework built on five key principles: customer-first, iterative delivery, clear ownership, data-informed decisions, and psychological safety.

### Lifecycle Phases

| Phase | Purpose |
|-------|---------|
| **Initiation** | Validate business need, align stakeholders, create a one-pager, and decide go/no-go for planning. |
| **Planning** | Break work into shippable increments, define a backlog with acceptance criteria, set milestones, and document risks. |
| **Execution** | Build, test, review, and iterate; track progress via standups, PR reviews, and the project board. |
| **Release** | Deploy to staging and production, verify with smoke tests, and announce to stakeholders. |
| **Close & Retrospective** | Capture learnings, create action items, and drive continuous improvement. |

### Key Roles

| Role | Responsibility |
|------|---------------|
| **Project Manager (PM)** | Coordinates delivery, schedules, risk management, and cross-team communication. |
| **Product Manager (PdM)** | Defines outcomes, owns the roadmap and backlog, and measures product success. |
| **Developers** | Implement features, write tests, participate in design and code reviews. |
| **QA / Testing** | Validate quality, verify acceptance criteria, and run smoke tests before release. |
| **Stakeholders** | Provide requirements, approve decisions, and receive regular project updates. |

### Core Artifacts

- **Project Charter / One-pager** — problem statement, goal, success metrics, timeline.
- **Prioritized Backlog** — itemized work with acceptance criteria, estimates, and owners.
- **Definition of Done (DoD)** — shared quality bar for completing any backlog item.
- **Risk Register** — ID, description, impact, likelihood, owner, mitigation, and status.
- **Release Plan & Release Notes** — milestone map, deployment checklist, and change summary.
- **Retrospective Notes** — what went well, improvements, and tracked action items.

### Communication Cadence & Escalation

- **Daily standups** (15 min) — progress, blockers, dependencies.
- **Weekly PM + PdM sync** — status, risks, roadmap alignment.
- **Monthly stakeholder updates** — milestone progress, key decisions, upcoming work.
- **Sprint demo / review** — end-of-sprint showcase and feedback.
- **Escalation path:** Team → PM → Product Lead → Sponsor (security incidents follow the security incident runbook).
